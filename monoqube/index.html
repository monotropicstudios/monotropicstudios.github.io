What the MVP shows

This is a software reference model on a server, with a simulated sensor. It is not the production unit. We built a working reference prototype of the MonoQube runtime metering and attestation layer described in PCT/US26/39996 and tested it. Every number here was measured on November 22, 2026, or comes from a public source linked below.

The meter never touches the workload. In a 62 second metered run, 0 bytes of the payload's data showed up in the operating record. We planted a secret in the workload's data and scanned the record for it. It never appeared.

The record can't be quietly changed. We attacked it 10,000 times across ten methods: editing values, deleting, inserting, reordering, replaying, backdating, and forging signatures, including an attacker who rebuilds the whole hash chain. All 10,000 were caught. Clean records raised 0 false alarms in 200 checks. Rolling the record back to an earlier checkpoint is caught every time the auditor keeps the last checkpoint it received, which is how the system is meant to run.

It costs the workload almost nothing. With the meter on its own core, the workload ran 1.2% slower at the median. With the meter forced onto the same core, it ran 4.6% slower. The meter used about 6% of one core while sampling 1,000 times a second and signing once a second.

Signing keeps up with the meter. Each record is signed in 31 microseconds and verified in 86 microseconds (median). One core writes 220,000 records a second and checks 230,000 a second.

The math is right. Against exact ground truth, metered energy was off by 0.002% on average across 200 one-minute sessions with a modeled 0.5% sensor. With calibration error added, error stayed under 0.62% in every session. Those energy figures show the metering math, not a physical sensor.

What auditors get

A plain JSON operating record. Each entry carries the pod, a sequence number, the bay, the device identity read from its tag, the authorization state, the power gate state, measured energy and peak power for the window, and a link to the entry before it. Signed checkpoints let anyone with the public key verify the full history without trusting the pod's storage or the hosted machine.

How we tested

The prototype runs the controller logic as a separate process from the workload, reads device identity from a tag reader the device can't write to, gates power on an authorization record the device can't change, and signs the record with Ed25519. The workload was SHA-256 and SHA3-256 over 32 MB, pinned to one core, timed over 78 runs per condition. Tamper tests ran 1,000 trials per attack type. Accuracy compared metered energy to the exact integral of a known load. This is a software reference model, not the production unit, and the sensor in the accuracy test is modeled. Physical sensor accuracy will be measured on the first hardware build. The code and raw results reproduce in about six minutes.
